Two F1 Race Tracker gotchas that waste time if you don't know them:

1. **`npm run build` (vite) empties `web/dist/`, deleting the tracked `web/dist/.gitkeep`.** That placeholder keeps the dir present for the Go gateway's `embed` of `web/dist`. After any web build, the working tree shows `D web/dist/.gitkeep` — restore it (`git checkout web/dist/.gitkeep`) and never commit its deletion.

2. **`bench/results.csv` and `bench/results.png` are the canonical Phase-1 1000-viewer benchmark artifacts.** A quick local load-test run overwrites them. Don't commit a quick/partial run over the canonical files — restore them unless you deliberately re-ran the full `BENCHMARKS.md` benchmark.

3. **The web ESLint config enforces strict `react-hooks` rules and CI lints at `--max-warnings 0`** (`npm run lint -- --max-warnings 0`). Two rules bite when writing hooks: (a) **no ref access during render** — can't do `if (!ref.current) ref.current = new X()` at the component top level; create the object inside a mount `useEffect(() => {...}, [])` instead; (b) **no synchronous `setState` in an effect body** (flagged as cascading renders) — `setState` inside a *called function* (e.g. a `pump()`/event handler) is fine, but a direct `setState()` at the top of an effect body errors. Design hooks so state-clearing happens in click handlers, not effects. `tsc -b` can pass while `eslint` still fails — always run the lint gate before committing FE work.

4. **This dev machine has no C compiler, so `CGO_ENABLED=0` and `go test -race` fails outright** (`go: -race requires cgo; enable cgo by setting CGO_ENABLED=1`) — confirmed via `where gcc`/`go env CC` both coming up empty. `scripts/test.sh`/`test.ps1` deliberately run plain `go test ./...` (no `-race`) for exactly this reason — CI (`ubuntu-latest`, where cgo/gcc are free) is where `-race` actually runs. Don't "fix" the local scripts to add `-race` — it breaks local test runs on this box for no gain, since CI already covers it.

5. **`ingest/live_signalr.py`'s real live-timing capture (`LIVE=1 ... ingest/live.py --live`) hangs forever, silently, with zero data and no error** — confirmed 2026-07-26 attempting to capture the real Hungarian GP race. Root cause: `fastf1.livetiming.client.SignalRClient` (which `live_signalr.py` wraps, default `no_auth=False`) now requires an active F1TV Access/Pro/Premium subscription. With no cached token it calls `fastf1.internals.f1auth.get_auth_token()`, which spawns a local HTTP server and blocks on `_auth_finished.wait()` for a browser-based login at `https://f1login.fastf1.dev?port=...` — but the login-URL `print()` never surfaces if the process is backgrounded/piped (stdout buffering), so it just looks hung. `no_auth=True` is *not* a workaround: it passes `access_token_factory=None` explicitly, which crashes `signalrcore.hub_connection_builder.with_url` with `TypeError: access_token_factory must be a function without params` (a real bug in fastf1 3.8.3's own `no_auth` path). This repo's `live_signalr.py`, `requirements-live.txt`, and docs have zero mention of F1TV/auth — the wrapper was written before this was ever tested against a real session and doesn't handle it. Also hit along the way: `docker-compose.yml`'s `redis` service deliberately has no host port mapping (compose-network-only), so running the live-capture script *on the host* (per the runbook) needs a local `docker-compose.override.yml` adding `ports: ["6379:6379"]` — don't add this to the tracked compose file, it's intentional that Redis isn't exposed.
6. **Running the static demo locally takes two steps that aren't written down anywhere.** `VITE_STATIC_DEMO=true` alone gives you a board stuck on "Warming up the timing feed", because the baked clip it fetches is gitignored and simply isn't there. First bake it with `go run ./cmd/bake-static` (writes `web/public/static-demo/monza-2024-race.ndjson`, ~23 MB), then create `web/.env.local` containing `VITE_STATIC_DEMO=true` — `*.local` is already gitignored, and setting it there rather than in the shell keeps `vite.config.ts`'s `process.env.VITE_STATIC_DEMO` check false, so `base` stays `/` and the dev server serves at plain `http://localhost:5173`. **Delete `web/.env.local` when you're done**: vitest loads it too, so it leaves `STATIC_DEMO` true during tests and every test that mocks `connectRace` fails with `Failed to parse URL from /static-demo/...`. Worth the setup — this is the only way to see the timing tower, map and overlay with real data without bringing up the whole docker stack.

**Why:** all six surface only at the verify/lint step or, for #5, only during an actual live session — committing past #1-4 breaks CI (or the local dev loop for #4); #5 means the "capture a real race" task cannot currently be completed without either (a) an F1TV subscription + completing the browser login once (token then caches to disk for future sessions), or (b) fixing/documenting the auth requirement in `live_signalr.py` first.
**How to apply:** before any commit during F1 work, check `git status` for the two artifacts and restore them; run `npm run lint -- --max-warnings 0` (not just build) on any new hook/component; run `go test ./...` locally (no `-race`) and trust CI for the race-detector pass. Before attempting another live capture: confirm F1TV subscription access first, and run the capture in the **foreground** (not backgrounded) so the login URL is actually visible — don't waste race time rediscovering the hang.
